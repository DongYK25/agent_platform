# 数据库操作

对照 `app/routers/users.py`。数据库会话来自 `SessionDep`，一次请求一个 `Session`，请求结束自动关闭。

表名看模型上的 `__tablename__`。当前 `User` 写的是 `users`。原生 SQL 里的表名必须和它一致。

## 一次请求里对象怎么变

客户端发来的是 JSON。函数参数写成 `UserCreate` 或 `UserUpdate` 之后，FastAPI 在进入函数之前就完成两件事：把 JSON 解析成这个类型，并按字段规则校验。校验失败直接返回 422，函数不会执行。这里不用自己 `json.loads`。

和数据库打交道的是表模型 `User`，不是 `UserCreate`。所以创建时要再转一次：

```python
db_user = User.model_validate(user)  # UserCreate -> User，此时还没写库
```

返回值如果是 `User`，`response_model=UserPublic` 会在写出响应前丢掉 `password` 等未声明字段。这也是校验，发生在出参，不访问数据库。

| 类型 | 作用 | 会不会访问数据库 |
| --- | --- | --- |
| `UserCreate` / `UserUpdate` | 校验请求 JSON | 否 |
| `User` | 对应表的一行 | 配合 `session` 才会 |
| `UserPublic` | 决定响应里留哪些字段 | 否 |

## Session：改完要不要提交

| 调用 | 做了什么 | 要不要 `commit` |
| --- | --- | --- |
| `session.get` / `session.exec(select(...))` | 查询 | 不要 |
| `session.add(obj)` | 把对象放进本次事务，INSERT 还没提交 | 要，之后 `commit` |
| 改已经查出的对象的属性 | 标记为待更新 | 要 |
| `session.delete(obj)` | 标记为待删除 | 要 |
| `session.commit()` | 把本次 INSERT / UPDATE / DELETE 真正提交 | — |
| `session.rollback()` | 撤销本次事务里还没提交成功的修改 | `commit` 抛错之后调用 |
| `session.refresh(obj)` | 用数据库里的当前行重新填这个对象 | 放在成功的 `commit` 之后 |

`add`、改属性、`delete` 都只改内存里的事务。不 `commit` 的话，请求结束、`Session` 关闭时这些修改会被丢掉。

`commit` 成功后，自增 `id` 才稳定地回到对象上。所以创建之后要 `refresh`，再把对象返回给客户端。删除之后对象已经不在表里，不要 `refresh`。

唯一约束（用户名、邮箱重复）是在 `commit` 时由数据库报出来的，不是在 `add` 时。所以 `try` 包住的是 `commit`：

```python
try:
    session.commit()
except IntegrityError:
    session.rollback()
    raise HTTPException(status_code=409, detail="Username or email already exists")
```

`rollback` 用来清掉这次失败的事务，否则同一个 `session` 不能继续用。

## 查

查询都不需要 `commit`，也不需要把 JSON 转成 `User`。路径参数和查询参数由 FastAPI 校验，例如 `user_id: int`、`limit` 的 `ge=1, le=100`。

按主键查一条，没有就得到 `None`：

```python
user = session.get(User, user_id)
```

查多条。`offset` / `limit` 就是分页：

```python
users = session.exec(select(User).offset(offset).limit(limit)).all()
```

带条件。`where` 里多个条件是并且（AND）：

```python
statement = select(User).where(User.username == "ada")
statement = select(User).where(User.username == "ada", User.email == "ada@example.com")
```

或者用 `or_`：

```python
from sqlmodel import or_

statement = select(User).where(or_(User.username == "ada", User.email == "ada@example.com"))
```

条件查询的结果不要和主键查询混用：

| 方法 | 结果 |
| --- | --- |
| `.first()` | 第一条；没有则 `None` |
| `.all()` | 列表；没有则 `[]` |
| `.one()` | 必须正好一条，否则抛异常 |

```python
user = session.exec(select(User).where(User.email == "ada@example.com")).first()
users = session.exec(select(User).where(User.full_name == "Ada")).all()
```

`session.exec(select(User))` 拿到的已经是 `User` 对象，不是 JSON，也不用再 `model_validate`。

## 增

顺序固定为：请求体已经是 `UserCreate` → 转成 `User` → `add` → `commit` → `refresh`。

```python
db_user = User.model_validate(user)
session.add(db_user)
session.commit()
session.refresh(db_user)
return db_user
```

`model_validate` 只做对象转换，不写库。格式不对的 JSON 到不了这一行。

## 改

先按主键把原行查出来。请求体是 `UserUpdate`，字段全是可选的。

`model_dump(exclude_unset=True)` 只保留客户端这次真正传来的字段。没传的字段不会被改成 `None`。

```python
# 请求体 {"full_name": "Ada Lovelace"}
user.model_dump(exclude_unset=True)
# {"full_name": "Ada Lovelace"}
```

写回对象并提交：

```python
db_user.sqlmodel_update(user.model_dump(exclude_unset=True))
session.add(db_user)
session.commit()
session.refresh(db_user)
```

`sqlmodel_update` 只改内存中的这一行。不 `commit` 就不会更新数据库。`session.get` 取出的对象本来就在这个 `session` 里，这里的 `add` 是把修改重新放进事务，和官方示例一致。

## 删

没有请求体，所以没有 JSON 转模型这一步。先查出对象，不存在就 404。

```python
session.delete(user)
session.commit()
```

`delete` 之后必须 `commit`，数据库里才会执行 `DELETE`。

## 原生 SQL

用 `sqlalchemy.text`，参数用 `:名字` 占位，值放进 `params`。不要把用户输入拼进 SQL 字符串。

原生语句不经过 `UserCreate` / `UserUpdate`。数据如果来自客户端，要先用 schema 校验，再把校验后的值放进 `params`。

查，不用 `commit`，得到的是 `Row`，不是 `User`：

```python
from sqlalchemy import text

row = session.exec(
    text("SELECT id, username, email FROM users WHERE username = :username"),
    params={"username": "ada"},
).first()

if row is not None:
    row.username
    dict(row._mapping)
```

增删改都要 `commit`：

```python
session.exec(
    text(
        "INSERT INTO users (username, email, password) "
        "VALUES (:username, :email, :password)"
    ),
    params={"username": "ada", "email": "ada@example.com", "password": "secret1"},
)
session.commit()

session.exec(
    text("UPDATE users SET full_name = :full_name WHERE id = :id"),
    params={"full_name": "Ada", "id": 1},
)
session.commit()

session.exec(
    text("DELETE FROM users WHERE id = :id"),
    params={"id": 1},
)
session.commit()
```

日常接口优先用 `select(User)` 和 `session.get`。那样返回的是 `User`，也能接着用 `response_model`。原生 SQL 适合统计、复杂条件，或者必须手写语句的时候。
